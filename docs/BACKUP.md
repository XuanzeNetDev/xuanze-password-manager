# 备份与迁移

这份文档只讲一件事：**怎么保证数据不丢，以及怎么把它搬到另一台机器上。**

先说结论，省得往下翻：

- **库文件不能搬，数据能搬。** `vault.xzvlt` 绑这台机器，换机器打不开；
  导出成 Excel 之后，数据可以在任何一台装了本软件的机器上导入回来。
- **迁移三步：旧机导出 → 新机建库 → 新机导入。**
- **唯一需要养成的习惯：定期导出。** 没有导出过的数据，机器坏了就真没了。

---

## 一、这套设计为什么长这样

本产品的库文件绑机器：除了主密码，密钥派生还混入本机 DPAPI 封存的随机串、
机器名与系统卷序列号。好处是「把 `vault.xzvlt` 拷走解不开」；
代价是这个文件只能在原机器原账户下打开。

于是一个问题立刻出现：*那数据怎么搬家？*

答案不是「放宽绑定」，而是**另开一条明确的通道**：导出 / 导入。
两条通道的分工是清楚的：

| | 防什么 | 什么时候用 |
|---|---|---|
| 库文件 + 机器绑定 | 文件被误同步、拷走、发错人 | 平时，什么都不用管 |
| 导出 Excel | 机器坏了、换机、重装系统 | 你要主动做的那一步 |

一个防意外，一个防灾难。它们不冲突，也不互相替代。

> **为什么不让库文件本身可迁？**
> 一旦那个文件能在任何机器上解开，它的安全性上限就等于主密码强度 ——
> 而你把它发给谁、同步到哪个网盘，就不再是你能控制的事了。
> 我们选择把「文件能不能被解开」和「数据能不能搬走」拆成两件事。

## 二、日常备份

**频率建议：每周一次；重要改动（新增/修改凭据）之后立刻一次。**
保留最近几份，别只留一份 —— 万一某次导出时手滑删错了条目，
上一份还能救。

```text
设置 → 导入 / 导出 → 导出
  ↓
选一个位置（系统另存为对话框）
  ↓
得到一个按专辑分工作表的 .xlsx
```

### 导出文件放哪

导出的是**明文**：整个库的账号、密码、密钥、备注都在里面。
落盘那一刻起，它就不受本产品保护了。

所以：

- **推荐**：BitLocker 加密的移动硬盘 / U 盘；7-Zip 加密压缩包；
  带独立密码的网盘保险箱；**只存离线介质**是最省心的选择。
- **不推荐**：桌面、下载文件夹、未加密的网盘同步目录、
  聊天软件的文件传输记录。

导出完成后的提示里有一句「文件是明文，用完请及时删除」——对临时导出成立；
如果是长期备份，请放进上面那种容器里，而不是删掉。

## 三、换机器 / 重装系统：三步

全程在界面上点，不需要命令行，也不需要动 `%APPDATA%`。

### 第一步：旧机器导出

设置 → 导入 / 导出 → 导出 → 输入主密码 → 选位置。
把得到的 `.xlsx` 拷到新机器（U 盘、网盘、局域网都行）。

> **重装系统的话，这一步必须在重装之前做完。**
> 重装之后 `%APPDATA%` 会被清空，绑定材料一起没了，
> 那时候再想从 `.xzvlt` 里拿数据已经不可能。

### 第二步：新机器建库

装好本软件，第一次打开会让你设主密码 —— 这会建一个**新库**
（新的库标识、新的本机绑定、新的文件）。

**这个密码是新库的密码，不需要和旧库一样。**
但请记住它：它是新库里唯一的那把钥匙。

### 第三步：新机器导入

设置 → 导入 / 导出 → 导入 → 选那份 `.xlsx` → 输入**新库**的主密码。

导入完成后界面会提示导入了多少条、跳过多少条。

### 导入会还原什么

| 字段 | 是否还原 |
|---|---|
| 名称、类型、账号、密码·密钥、网址、备注 | ✅ |
| 专辑（标签） | ✅ |
| 自定义字段（含「敏感」标记） | ✅ |
| 创建时间、更新时间 | ✅ |
| 过期时间 | ✅ |
| 使用次数（热度榜排序用） | ✅ |
| 条目 id | ❌ 新库里重新生成（id 只是本地标识） |
| 最后使用时间 | ❌ 置 0，热度按使用次数重排 |

不还原的只有「库本身」：新库是新文件，旧的 `vault.xzvlt` 迁移完之后可以删掉
（它是绑定旧机器的密文，留着也打不开）。

### 跳过是什么意思

导入时「名称 + 账号」都相同的条目会被跳过。这样同一个文件重复导入两次
不会变成双份，也不会因为密码改过而重复。

如果出现了**失败**（不是跳过），界面会带上原因，例如：

```text
全部/第 12 行「某个条目」：备注超过 1 MiB
```

这类条目需要先在自己的表格里改小，再单独导入一次。
不会出现「少了几条但什么都不说」的情况。

## 四、主密码忘了怎么办

**导出过的 Excel 仍然可以导入。** 导入时输的是新库的密码，
和旧库的主密码无关。

- 有导出 → 新机器（或重装后）建新库 → 导入 → 数据回来
- 没有导出 → 数据无法恢复。我们没有任何后门，也没有「重置密码」的入口

这就是为什么上面反复强调「尽早导出一次」。

## 五、表格格式（万一你要手工处理）

导入器读的是固定表头，但**按列名对位，不按位置**，所以：

- 列顺序可以调整
- 中间可以插自己的批注列（不认识的列会被忽略）
- 可以只保留前面 9 列（缺的列按空处理，仍能导入）

| 列 | 名称 | 说明 |
|---|---|---|
| 1 | 名称 | **必需**。空名称的行会被跳过 |
| 2 | 类型 | 登录 / 密钥 / 笔记 / 银行卡 / 凭据。认不出按「登录」处理 |
| 3 | 账号 | |
| 4 | 密码 / 密钥 | |
| 5 | 网址 | |
| 6 | 专辑 | 多个用逗号分隔；也会并入所属工作表的名字 |
| 7 | 备注 | |
| 8 | 更新时间 | `YYYY-MM-DD HH:MM:SS`（UTC） |
| 9 | 自定义字段 | `字段名=值`，多个用 `; ` 分隔；字段名前加 `!` 表示敏感 |
| 10 | 创建时间 | 同上格式 |
| 11 | 过期时间 | 留空 = 不过期 |
| 12 | 使用次数 | 整数 |

自定义字段的转义规则（手工编辑时才需要在意）：

| 写在值里 | 导出后长什么样 | 说明 |
|---|---|---|
| `;` | `\;` | 分号是字段之间的分隔符，出现在值里必须转义 |
| `\` | `\\` | 反斜杠是转义符，自己也要转义 |
| `=` | `=` | **不用转义**：解析时只认第一个 `=`，后面的全算值 |

字段**名**里的 `=` 会被转义成 `\=`（名字只到第一个 `=` 为止）。
如果你在 Excel 里手写这一列，记住半角分号要写成 `\;`，否则会被当成分隔符。

### 用 Excel 打开改一格再保存，会不会读不了

不会。读取端照顾了 Excel 重存之后的两种变化：

1. **空单元格被省略** —— 按每个单元格自己的地址（`r="C7"` 里的 `C`）定位，
   不按出现顺序，所以不会整行左移
2. **字符串挪进共享字符串表**（`sharedStrings.xml`）—— 读取端认这种结构

真正读不了的情况只有一种：表头被改成认不出来的样子（比如「名称」这一列
被改名或删掉），那时整张表会被跳过，并提示表头不支持。

## 六、常见误区

**「把 `%APPDATA%\cn.xuanze.vault\` 整个目录备份起来就行了吧？」**

不行。那个目录里的 `machine.bind` 是 DPAPI 绑当前账户的，换机器解不开。
只有 Excel 能跨机恢复。目录可以备份（它防的是同一台机器上的误删），
但它不能当迁移方案。

**「只备份 `vault.xzvlt` 呢？」**

那一份备份在任何别的机器上都打不开，密码正确也没用。

**「那我把 `machine.bind` 也一起拷过去？」**

DPAPI 是用户级加密，换机器/换账户就解不开 —— 拷过去也没用。

**「导出一次就够了，以后不用了。」**

每次改动之后库就和上一份导出不一致了。建议固定节奏，或者至少在
「这次新增了不少东西」之后补一次。

**「导出太麻烦了，能不能自动定时导出？」**

当前版本没有这个功能。自动定时导出意味着明文会以固定节奏落在硬盘上，
那是另一个需要认真设计的风险面，不在 v1.0.0 范围内（见
[ROADMAP](ROADMAP.md)）。

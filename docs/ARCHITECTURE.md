# 璇泽密钥库 · 架构说明

这一份讲**为什么这么切**，`docs/FORMAT.md` 讲**格式是什么**，`docs/PERFORMANCE.md`
讲**快在哪、哪里没快起来**。三份不重复。

---

## 1. 分层

```
┌──────────────────────────────────────────────────────────┐
│  src/            前端界面（原生 TS，零框架）               │
│                  · 只做展示与交互                          │
│                  · 明文只在「显示」时缓存，隐藏/锁定即清    │
├──────────────────────────────────────────────────────────┤
│  src-tauri/      桌面壳（Tauri v2）                        │
│                  · 命令层：把 UI 意图翻译成 core 调用      │
│                  · 会话状态机：解锁 / 自动锁 / 手动锁      │
│                  · 剪贴板：写入 + 定时清除                 │
│                  · 导入导出：xlsx 读写（手写 OOXML）        │
│                  · 本机绑定：DPAPI 封存的 pepper           │
├──────────────────────────────────────────────────────────┤
│  crates/xz-core/  核心库（纯 Rust，无 UI 依赖）            │
│                  · 文件格式编解码                          │
│                  · 密码学（Argon2id / AES-GCM / HKDF）     │
│                  · 内存索引与搜索                          │
│                  · 内存擦除                                │
├──────────────────────────────────────────────────────────┤
│  crates/xz-bench/ 基准：同一套核心的性能观测口             │
└──────────────────────────────────────────────────────────┘
```

**为什么把安全核心独立成 crate：**

1. 它不依赖 Tauri、不依赖任何 UI 框架 —— 换壳（换到 egui、换到 WinUI、换到 Web）
   完全不影响它。
2. 格式与加密逻辑只有一份实现，可以脱离界面单独验证 ——
   `cargo test -p xz-core` 一秒出结果，不需要启动窗口。
   排查诡异问题时，先在这个层级复现，能立刻判断是界面问题还是核心问题。

## 2. 三个关键设计决定

### 2.0 绑定材料跟着文件走（v3 起）

这是 v1.0.0 里改动最大的一处，也是唯一一处「原本会把用户数据弄丢」的设计问题。

早期版本把绑定材料只放在 `%APPDATA%\cn.xuanze.vault\machine.bind`（DPAPI 封存），
pepper 里还混了**计算机名 + C 盘卷序列号**。两条路都脆：

- `machine.bind` 会被清掉（重装系统、清配置、换账户）
- 计算机名右键就能改，卷序列号格式化就重新生成

于是「重装系统」= 数据永久报废，密码正确也没用。

现在的做法：

```text
binding_secret = 32 字节随机（256 bit）
pepper         = "xzvlt-bind-v2\0" || binding_secret

binding_secret 存两份：
  ① %APPDATA%\...\machine.bind      DPAPI 封存          日常快路径
  ② 库文件里的绑定块                 硬件指纹加密       重装系统后靠它
     （硬件指纹 = SMBIOS Type 1 的 UUID，重装不变、换主板才变）
```

结果：改计算机名 / 重装系统 / 格式化重装 → 能开；换主板 / 换系统盘 / 换电脑 → 打不开。
后者是想要的效果，前者是之前不该有的损失。

**这不算「取消绑定」。** 文件被拷到别的机器时，绑定块解不开（硬件指纹不同），
库依然打不开。变的只是「同一台机器上系统层面的变动不再算数」。

细节见 `docs/FORMAT.md` §1.1 与 §3.1.1。

### 2.1 索引与正文分开加密

索引（名称、账号、网址、标签）和正文（秘密、备注、自定义字段）用**不同的子密钥**加密。

理由：两者的访问模式完全不同。

- 索引要常驻内存、每次击键都读它；
- 正文只在「看详情」或「复制」时读一条。

分开之后：索引可以只存精简版（不含秘密），一万条也就几 MB；
而且万一将来要做「只给搜索结果的只读预览」，不需要解密正文。

代价：保存时两段各自加密，多一次 AES 调用（几十微秒，忽略）。

### 2.2 主密钥派生只做一次（每次解锁）

Argon2id 是唯一的慢操作（默认档 510 ms）。日常路径上它**只在打开时跑**：

- 保存：直接用内存里的主密钥加密，不重跑 KDF
- 换主密码：重跑 KDF + 换盐 + 全量重加密

这条决定了整个产品的体感。如果每次保存都重跑 KDF，用户每改一个字
就要等半秒，那就没有人愿意用。

**有一个例外是刻意的：** 导出明文、导入、改主密码、开关免密码模式这四件事，
都会把 KDF 重跑一遍。因为它们要回答的问题是「你知不知道主密码」——
而唯一正确的判据是重新派生，看能不能得到同一把主密钥
（`Vault::verify_password_bound`）。

这半秒的代价换来的是那四道门真的存在。实现上把 KDF 放在锁外、
线程池里跑，界面不会冻住；错误和成功都走同一套等待提示。
`KdfParams` 的档位见 `docs/PERFORMANCE.md` §2。

### 2.3 秘密不进索引，也不可搜索

`IndexItem` 里没有 `secret` 字段，也没有任何敏感自定义字段的值。
这条有单测守着（`index_never_carries_secrets`），而且搜索逻辑里
根本没有能碰到秘密的路径（`secrets_never_searchable`）。

这是一个**有意的功能限制**：用户不能搜「哪个条目的密码里含 acme」。
换来的是索引可以放心常驻内存、放心落盘（它本身就是加密的）。

### 2.4 导出 / 导入是正式的数据通道，不是附赠功能

库文件绑定硬件，所以「换机器」这件事必须有一条通道。这条通道就是
加密备份（`.xzbak`）—— 它的地位和「保存」同级，不是导出个报表给人看的附属品。

**导出物是密文。** 早期版本导出的是明文 xlsx，于是产品形成了这样一个循环：
「绑定机器」要求用户定期备份，而「备份」又把全库明文摊到磁盘上 ——
用一个更大的泄露风险去对冲一个可用性风险。现在是
`Argon2id 64 MiB × 3 + AES-256-GCM` 的容器，里面才是 xlsx。

由此产生几条硬约束，写在这里是因为它们看着像过度设计，其实都是被真实场景逼出来的：

| 约束 | 为什么 |
|---|---|
| **逐字段对称** | 导出 12 列就得还原 12 列。丢掉自定义字段或时间戳，「灾备」就是空话 |
| **按列名对位，不按位置** | 用户会在 Excel 里拖动列、插批注列。按位置对位，改一格列序就串位 |
| **按单元格地址读** | Excel 会省略空单元格。按出现顺序读会整行左移，密码落进「网址」列 |
| **认共享字符串表** | Excel 覆盖保存会把内联字符串改写成 `sharedStrings.xml` + 下标 |
| **自定义字段用可逆编码** | `名字=值` 直接拼串再拆，遇到值里的 `;` `=` 就会静默改数据 |
| **导入同时吃两种文件** | `.xzbak` 和裸 `.xlsx` 都收：别人手工整理的表也能进来 |

对应的验证是一个端到端测试：`entry_survives_export_then_import`
（`src-tauri/src/export.rs`）把一条带自定义字段、三个时间戳、使用次数的条目
走完整条「表格 → 条目」的路，逐个字段比对。CI 的桌面壳 job 会执行它。

前端在这条链路上只有一个职责：**不要自己判断「本机有没有库」**。
那个判断必须来自后端（登记表 + 文件是否存在），见 `commands.rs::vault_exists`。

## 3. 会话生命周期

```text
           ┌──────────────────────────────────────┐
           │            Locked                    │
           └──────────────────────────────────────┘
              │ create(pw)          │ open(pw)
              ▼                     ▼
           ┌──────────────────────────────────────┐
           │           Unlocked                   │
           │  vault / last_activity / auto_lock   │
           └──────────────────────────────────────┘
              │ lock()  │ autolock（闲置超时）
              └─────────┴──────────► Locked
```

- **自动锁定靠单调时钟**（`Instant`），不是墙钟。系统时间被改（时区、手动调表、
  NTP 回拨）都不会绕过它。
- **闲置时长可调**（设置里 1 / 5 / 15 / 30 分钟，默认 5），存在后端文件里、
  由后端执行；前端只是显示与设置。放 `localStorage` 的话清一次缓存就回到默认值，
  而用户以为自己设的是 30 分钟。
- **前端每次交互上报 `touch_activity`**，但做了 6 秒节流 —— 鼠标移动是每秒几十次的事件，
  每次都跨 IPC 是不必要的开销。6 秒足够，因为最短的自动锁定档是 1 分钟。
- **解锁有绝对上限**（8 小时）：一直在用也会到点强制重新验证身份。
- **锁定时同时清剪贴板**（只清自己写进去的那份）。

## 4. 剪贴板的安全边界

写剪贴板时就定好 TTL：敏感内容 15 秒、普通内容 60 秒。实现上做了三件事：

1. 记下写入内容的**指纹**和时间，外加一个**代际号**；
2. 到点时读回剪贴板，**内容还是一样才清**；
3. 清不掉（剪贴板正被别的程序占用）就**保留指纹，下一轮再试** ——
   不能把失败当成已清，否则那份密码会一直躺在剪贴板里。

第 2 步是关键：如果用户在这段时间里复制了别的东西，我们就不动它。
粗暴清空会踩掉用户刚复制的内容，这种体验比不清还糟。代际号解决的是反过来的
那个竞态：清理线程判定到期的同一刻用户又复制了一次，没有代际校验就会
把**刚写进去的那份**清掉 —— 表现为「复制了，粘贴出来是空的」。

**目前界面上所有的复制动作都按敏感内容处理（15 秒）**：表格里那个复制按钮
拿的是密钥。底层也支持非敏感内容走 60 秒（`copy_to_clipboard` 的 `sensitive`
参数），留给将来的「复制账号」按钮 —— 现在还没有这个按钮。

这条边界还必须写清楚：**它挡不住剪贴板历史工具**（Windows 自带的 `Win+V`、
各种粘贴板管理器会把内容留在它们自己的存储里）。真要更安全，就得自己
实现一个「点击即输入」的假键盘接口，排在 v1.1。

## 5. 错误处理原则

核心库的错误分两类：

| 类别 | 例子 | 对外表现 |
|---|---|---|
| **结构性错误** | 魔数不对、版本过高、段越界 | 明确告知「文件有问题」 |
| **密码学错误** | GCM 认证失败、校验块不符 | 统一成「密码错误或文件被篡改」 |

第二类**不区分**是密码错还是被篡改 —— 这是密码学上的标准做法，
给攻击者任何区分信号都是信息泄漏。

第一类的细节（比如「索引段越界」）只出现在开发者日志里，UI 上仍是一句话。

## 6. 已知的取舍

| 取舍 | 选择了什么 | 放弃了什么 |
|---|---|---|
| 存储格式 | 自研格式（版本 2）+ 完整规范 | 兼容 KDBX（能直接吃 KeePass 用户） |
| 正文格式 | JSON | 二进制格式的 30% 体积优势 |
| 保存策略 | 全量重加密 | 大库的增量写入（5 万条时 400 ms） |
| 搜索 | 内存全量扫描 + 流式 Top-K | n-gram 倒排（对中文更友好，索引翻倍） |
| 前端 | 原生 TS 手写 DOM | 组件化框架（开发速度，换来更快的冷启动） |
| 秘密可见性 | 索引里绝不含秘密 | 「按密码内容搜索」 |

每一条都是「为了这个产品的定位」选的，不是「做不到」。
要换的话，接口在，改内部实现即可。

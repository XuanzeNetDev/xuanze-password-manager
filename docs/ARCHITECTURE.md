# 璇泽密钥库 · 架构说明

这一份讲**为什么这么切**，`docs/FORMAT.md` 讲**格式是什么**，`docs/PERFORMANCE.md`
讲**快在哪、哪里没快起来**。三份不重复。

## 1. 分层

```
┌──────────────────────────────────────────────────────────┐
│  src/            前端界面（原生 TS，零框架）               │
│                  · 只做展示与交互                          │
│                  · 明文只在「显示」时缓存，隐藏/锁定即清    │
├──────────────────────────────────────────────────────────┤
│  src-tauri/      桌面壳（Tauri v2）                        │
│                  · 命令层：把 UI 意图翻译成 core 调用      │
│                  · 会话状态机：解锁 / 自动锁 / 手动锁      │
│                  · 剪贴板：写入 + 定时清除                 │
│                  · 导入导出：xlsx 读写（手写 OOXML）        │
│                  · 本机绑定：DPAPI 封存的 pepper           │
├──────────────────────────────────────────────────────────┤
│  crates/xz-core/  核心库（纯 Rust，无 UI 依赖）            │
│                  · 文件格式编解码                          │
│                  · 密码学（Argon2id / AES-GCM / HKDF）     │
│                  · 内存索引与搜索                          │
│                  · 内存擦除                                │
├──────────────────────────────────────────────────────────┤
│  crates/xz-bench/ 基准：同一套核心的性能观测口             │
└──────────────────────────────────────────────────────────┘
```

**为什么把安全核心独立成 crate：**

1. 它不依赖 Tauri、不依赖任何 UI 框架 —— 换壳（换到 egui、换到 WinUI、换到 Web）
   完全不影响它。
2. 格式与加密逻辑只有一份实现，可以脱离界面单独验证 ——
   `cargo test -p xz-core` 一秒出结果，不需要启动窗口。
   排查诡异问题时，先在这个层级复现，能立刻判断是界面问题还是核心问题。
3. 单测可以不启窗口地跑，`cargo test -p xz-core` 一秒出结果。

## 2. 三个关键设计决定

### 2.1 索引与正文分开加密

索引（名称、账号、网址、标签）和正文（秘密、备注、自定义字段）用**不同的子密钥**加密。

理由：两者的访问模式完全不同。

- 索引要常驻内存、每次击键都读它；
- 正文只在「看详情」或「复制」时读一条。

分开之后：索引可以只存精简版（不含秘密），一万一千里条目也就几 MB；
而且万一将来要做「只给搜索结果的只读预览」，不需要解密正文。

代价：保存时两段各自加密，多一次 AES 调用（几十微秒，忽略）。

### 2.2 主密钥派生只做一次

Argon2id 是唯一的慢操作（默认档 510 ms）。它**只在打开时跑**：

- 保存：直接用内存里的主密钥加密，不重跑 KDF
- 换主密码：重跑 KDF + 换盐 + 全量重加密（这是唯一需要重跑的场景）

这条决定了整个产品的体感。如果每次保存都重跑 KDF，用户每改一个字
就要等 510 ms，那就没有人愿意用。

### 2.3 秘密不进索引，也不可搜索

`IndexItem` 里没有 `secret` 字段，也没有任何敏感自定义字段的值。
这条有单测守着（`index_never_carries_secrets`），而且搜索逻辑里
根本没有能碰到秘密的路径（`secrets_never_searchable`）。

这是一个**有意的功能限制**：用户不能搜「哪个条目的密码里含 acme」。
换来的是索引可以放心常驻内存、放心落盘（它本身就是加密的）。

## 3. 会话生命周期

```text
           ┌──────────────────────────────────────┐
           │            Locked                    │
           └──────────────────────────────────────┘
              │ create(pw)          │ open(path, pw)
              ▼                     ▼
           ┌──────────────────────────────────────┐
           │           Unlocked                   │
           │  vault / last_activity / auto_lock   │
           └──────────────────────────────────────┘
              │ lock()  │ autolock（闲置超时）
              └─────────┴──────────► Locked
```

- **自动锁定靠单调时钟**（`Instant`），不是墙钟。系统时间被改（时区、手动调表、
  NTP 回拨）都不会绕过它。
- **前端每次交互上报 `touch_activity`**，但做了 6 秒节流 —— 鼠标移动是每秒几十次的事件，
  每次都跨 IPC 是不必要的开销。6 秒足够，因为最短的自动锁定档也是 1 分钟。
- **锁定时同时清剪贴板**（只清自己写进去的那份）。

## 4. 剪贴板的安全边界

复制的密钥按敏感度区分：密码/密钥 15 秒、账号网址 60 秒后自动清除。实现上做了两件事：

1. 记下写入内容的**指纹**和时间；
2. 到点时读回剪贴板，**内容还是一样才清**。

第 2 步是关键：如果用户在这段时间里复制了别的东西，我们就不动它。
粗暴清空会踩掉用户刚复制的内容，这种体验比不清还糟。

这条边界必须写清楚：**它挡不住剪贴板历史工具**（Windows 自带的 `Win+V`、
各种粘贴板管理器会把内容留在它们自己的存储里）。真要更安全，就得自己
实现一个「点击即输入」的假键盘接口，那是 v2 的事。

## 5. 错误处理原则

核心库的错误分两类：

| 类别 | 例子 | 对外表现 |
|---|---|---|
| **结构性错误** | 魔数不对、版本过高、段越界 | 明确告知「文件有问题」 |
| **密码学错误** | GCM 认证失败、校验块不符 | 统一成「密码错误或文件被篡改」 |

第二类**不区分**是密码错还是被篡改 —— 这是密码学上的标准做法，
给攻击者任何区分信号都是信息泄漏。

第一类的细节（比如「索引段越界」）只出现在开发者日志里，UI 上仍是一句话。

## 6. 已知的取舍

| 取舍 | 选择了什么 | 放弃了什么 |
|---|---|---|
| 存储格式 | 自研 v1 + 完整规范 | 兼容 KDBX（能直接吃 KeePass 用户） |
| 正文格式 | JSON | 二进制格式的 30% 体积优势 |
| 保存策略 | 全量重加密 | 大库的增量写入（5 万条时 400 ms） |
| 搜索 | 内存全量扫描 + 流式 Top-K | n-gram 倒排（对中文更友好，索引翻倍） |
| 前端 | 原生 TS 手写 DOM | 组件化框架（开发速度，换来更快的冷启动） |
| 秘密可见性 | 索引里绝不含秘密 | 「按密码内容搜索」 |

每一条都是「为了这个产品的定位」选的，不是「做不到」。
要换的话，接口在，改内部实现即可。

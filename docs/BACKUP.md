# 备份与迁移

这份文档只讲两件事：**怎么保证数据不丢，以及怎么把它搬到另一台机器上。**

先说结论：

- **库文件不能跨硬件，但能跨系统。** 重装系统、清 `%APPDATA%`、改计算机名，
  都不会影响它；换主板、换系统盘、换电脑才会打不开。
- **备份是密文。** 「导出备份」得到的是一个 `.xzbak` 文件，外面用
  Argon2id + AES-256-GCM 包着，磁盘上不会出现明文表格。
- **唯一要养成的习惯：定期导出那个 `.xzbak`。** 没有它，换硬件之后数据就真没了。

---

## 一、先分清三种情况

这三种情况的处理方式完全不同，别混：

| 你做了什么 | 库文件还能开吗 | 要做什么 |
|---|---|---|
| 重装系统 / 格式化 C 盘（硬件没动） | **能** | 把 `vault.xzvlt` 放回 `%APPDATA%\cn.xuanze.vault\`，直接打开 |
| 改计算机名 | **能** | 什么都不用做 |
| 换主板 / 换系统盘 / 换电脑 | 不能 | 用之前导出的 `.xzbak` 导入 |
| 忘了主密码 | 不能 | 用之前导出的 `.xzbak` 新建库后导入 |

**为什么重装系统还能开。** 绑定材料有两份：一份在 `%APPDATA%`（DPAPI 封存，
方便日常），另一份**在库文件自己里面**，用主板身份加密。
系统重装会清掉前者，但后者跟着文件走 —— 主板还是那块主板，就能解开。

**为什么换硬件就打不开。** 两份材料的解封都依赖硬件身份（主板 SMBIOS UUID）。
换了硬件，哪一份都解不开 —— 这正是「设备绑定」想要的效果。

## 二、日常备份

**频率建议：每月一次；重要改动（新增/修改凭据）之后立刻一次。**
保留最近几份，别只留一份。

```text
设置 → 备份 → 导出备份
  ↓
输主密码（证明操作者是本人）
设一个备份密码（给这个文件上锁，至少 8 位）
  ↓
选一个位置
  ↓
得到一个 璇泽密钥库-YYYY-MM-DD.xzbak（2 MB 上下）
```

### 这个文件里是什么

一份完整的 xlsx（按专辑分工作表），但整体用 Argon2id 64 MiB × 3 派生 +
AES-256-GCM 加密过。**磁盘上从头到尾不出现明文表格。**

为什么不直接用 Excel 的密码保护：OOXML 那套（ECMA-376）被 hashcat 一类工具
穿得很透。这里要保护的是「全部账号密码」，不能拿一个已知能被跑穿的锁去锁它。

### 备份密码设成什么

- **可以设成和主密码一样** —— 少记一个，适合大多数人
- **也可以另设一个** —— 万一某一处泄露，影响面小一点

**忘了备份密码，这个文件就打不开了。** 我们没有后门。

### 放哪

因为文件本身已经是密文，位置的要求比过去宽松很多：

- 网盘、U 盘、移动硬盘都可以
- 想再稳一点：放两份，一份在线一份离线
- 不用再额外套加密压缩包 —— 外层已经加密过了

## 三、换硬件 / 换电脑：三步

全程在界面上点，不需要命令行，也不需要碰 `%APPDATA%`。

| 步骤 | 在哪 | 做什么 |
|---|---|---|
| 1 | 旧机器 | 设置 → 备份 → 导出备份。把 `.xzbak` 拷到新机器 |
| 2 | 新机器 | 装好软件，第一次打开照提示设主密码 —— 这会建一个**新库** |
| 3 | 新机器 | 设置 → 备份 → 导入，选那个 `.xzbak`，输**新库**的主密码 + 当时的**备份密码** |

导入完成后界面会提示导入了多少条、跳过多少条。

### 导入会还原什么

| 字段 | 是否还原 |
|---|---|
| 名称、类型、账号、密码·密钥、网址、备注 | ✅ |
| 专辑（标签） | ✅ |
| 自定义字段（含「敏感」标记） | ✅ |
| 创建时间、更新时间 | ✅ |
| 过期时间 | ✅ |
| 使用次数（热度榜排序用） | ✅ |
| 条目 id | ❌ 新库里重新生成（id 只是本地标识） |
| 最后使用时间 | ❌ 置 0，热度按使用次数重排 |

不还原的只有「库本身」：新库是新文件，旧的 `vault.xzvlt` 迁移完之后可以删掉
（它是绑定旧硬件的密文，留着也打不开）。

### 跳过是什么意思

导入时「名称 + 账号」都相同的条目会被跳过。这样同一个文件重复导入两次
不会变成双份，也不会因为密码改过而重复。

如果出现了**失败**（不是跳过），界面会带上原因，例如：

```text
全部/第 12 行「某个条目」：备注超过 1 MiB
```

这类条目需要先在自己的表格里改小，再单独导入一次。
不会出现「少了几条但什么都不说」的情况。

## 四、重装系统：什么都不用做

如果只是系统坏了重装、硬件没换：

1. 重装前把整个 `%APPDATA%\cn.xuanze.vault\` 目录**连同 `vault.xzvlt` 一起**拷走
   （或者至少把 `vault.xzvlt` 单独存好）
2. 重装完，装回软件
3. 把 `vault.xzvlt` 放回 `%APPDATA%\cn.xuanze.vault\`
4. 打开软件，输主密码，直接进

**不需要导入。** 绑定材料在文件里，主板没变就能解开。

> 唯一要注意的是：重装后 `%APPDATA%` 里那个 `machine.bind` 没了，
> 但那是**日常快路径**，不是必需品 —— 程序会自动改走文件里那份。

## 五、主密码忘了

用之前导出的 `.xzbak`：

1. 新机器（或同一台机器重装后）建一个新库，设一个新主密码
2. 设置 → 备份 → 导入
3. 选那个 `.xzbak`，输入**新库的主密码** + 原来的**备份密码**

数据回来。旧库不用管 —— 它的主密码已经没用了。

**如果备份密码和主密码是同一个**，那等于两把锁共用一把钥匙：
忘记主密码时备份也打不开。这也是「另设一个备份密码」的价值所在 ——
两个密码分别记在不同地方，任一处泄露都不至于全失。

## 六、表格格式（万一你要手工处理）

`.xzbak` 里面是一份 xlsx。导入器读的是固定表头，但**按列名对位，不按位置**：

- 列顺序可以调整
- 中间可以插自己的批注列（不认识的列会被忽略）
- 可以只保留前面 9 列（缺的列按空处理，仍能导入）

| 列 | 名称 | 说明 |
|---|---|---|
| 1 | 名称 | **必需**。空名称的行会被跳过 |
| 2 | 类型 | 登录 / 密钥 / 笔记 / 银行卡 / 凭据。认不出按「登录」处理 |
| 3 | 账号 | |
| 4 | 密码 / 密钥 | |
| 5 | 网址 | |
| 6 | 专辑 | 多个用逗号分隔；也会并入所属工作表的名字 |
| 7 | 备注 | |
| 8 | 更新时间 | `YYYY-MM-DD HH:MM:SS`（UTC） |
| 9 | 自定义字段 | `字段名=值`，多个用 `; ` 分隔；字段名前加 `!` 表示敏感 |
| 10 | 创建时间 | 同上格式 |
| 11 | 过期时间 | 留空 = 不过期 |
| 12 | 使用次数 | 整数 |

自定义字段的转义规则（手工编辑时才需要在意）：

| 写在值里 | 导出后长什么样 | 说明 |
|---|---|---|
| `;` | `\;` | 分号是字段之间的分隔符，出现在值里必须转义 |
| `\` | `\\` | 反斜杠是转义符，自己也要转义 |
| `=` | `=` | **不用转义**：解析时只认第一个 `=`，后面的全算值 |

字段**名**里的 `=` 会被转义成 `\=`（名字只到第一个 `=` 为止）。

### 用 Excel 打开改一格再保存，会不会读不了

不会。读取端照顾了 Excel 重存之后的两种变化：

1. **空单元格被省略** —— 按每个单元格自己的地址（`r="C7"` 里的 `C`）定位，
   不按出现顺序，所以不会整行左移
2. **字符串挪进共享字符串表**（`sharedStrings.xml`）—— 读取端认这种结构

真正读不了的情况只有一种：表头被改成认不出来的样子（比如「名称」这一列
被改名或删掉），那时整张表会被跳过，并提示表头不支持。

## 七、常见误区

**「把 `%APPDATA%\cn.xuanze.vault\` 整个目录备份起来就行了吧？」**

这台机器上重装系统可以这么干（见第四节）。换硬件不行 ——
`machine.bind` 和库里的绑定块都跟硬件绑着。换硬件要用 `.xzbak`。

**「只备份 `vault.xzvlt` 呢？」**

同一台机器重装系统够用。换硬件不行。

**「导出成 Excel 更保险，反正 Word 也能打开。」**

以前的版本确实是明文 xlsx，现在默认是 `.xzbak`（密文）。
如果确实需要一份能被别的工具直接读的表格（比如导进别的密码管理器），
目前没有界面入口 —— 需要的话只能先导出备份，再用本软件导入到临时库里手动转存。

**「导出一次就够了，以后不用了。」**

每次改动之后库就和上一份备份不一致了。建议固定节奏，或者至少在
「这次新增了不少东西」之后补一次。

**「导出太麻烦了，能不能自动定时备份？」**

当前版本没有。自动定时导出意味着密文会以固定节奏落在磁盘上，
那是另一个需要认真设计的风险面（何况还要保管备份密码），
不在 v1.0.0 范围内。
